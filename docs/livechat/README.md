# چت آنلاین پشتیبانی (جایگزین گفتینو)

این سند سناریوی کامل چت آنلاین آرکان گلد را شرح می‌دهد: ویجت چت در اپ ← ربات منوی پاسخ‌های آماده ← حالت هوشمند ← اتصال به کارشناس (صف، تخصیص، انتقال) ← حالت آفلاین و پیامک ← امتیازدهی و گزارش. چت سرویس داخلی خود آرکان گلد است (بدون اسکریپت و سرور شخص ثالث) و همه‌ی بخش‌های آن از پنل مدیریت قابل تنظیم است.

## ۱. سناریوها

| # | سناریو | رفتار |
|---|--------|-------|
| ۱ | بازدیدکننده (مهمان یا کاربر واردشده) دکمه‌ی چت را می‌زند | پیام خوشامد و پرسش «در چه موردی سوال دارید؟» با دکمه‌های منوی اصلی و «گفتگو با کارشناس» نمایش داده می‌شود. تا انتخاب یا نوشتن پیام، گفتگویی ثبت نمی‌شود |
| ۲ | انتخاب یک گزینه‌ی منو (مثلاً «اطلاع از ساعات کاری») | گزینه‌ی انتخابی به‌عنوان پیام بازدیدکننده و پاسخ ربات ثبت می‌شود؛ زیر پاسخ زیرگزینه‌ها و دکمه‌های «بازگشت»، «منوی اصلی» و «گفتگو با کارشناس» می‌آیند. متغیرهای `{{working_hours}}`، `{{gold_price}}` و `{{name}}` هنگام ارسال جایگزین می‌شوند |
| ۳ | گزینه‌ی «پیوند» (مثلاً ورود به صفحه‌ی استعلام اصالت) | صفحه‌ی داخلی اپ (`/...`) در همان برگه یا نشانی https در برگه‌ی جدید باز می‌شود |
| ۴ | گزینه‌ی «اتصال به کارشناس» (مثلاً «گفتگو با کارشناس مالی») | گفتگو با دپارتمان همان گزینه (واحد مالی) به صف کارشناسان می‌رود |
| ۵ | بازدیدکننده به‌جای انتخاب، سؤالش را می‌نویسد | **حالت هوشمند**: پرسش با پایگاه دانش و کلمات کلیدی منو مقایسه می‌شود؛ پاسخ مطمئن مستقیم داده و «این پاسخ مفید بود؟» پرسیده می‌شود؛ پاسخ‌های محتمل به‌صورت «شاید منظورتان…» پیشنهاد می‌شوند؛ در غیر این صورت پاسخ جایگزین + منو، و پرسش در «پرسش‌های بی‌پاسخ» ثبت می‌شود |
| ۶ | نوشتن «کارشناس»، «اپراتور»، … | مستقیم درخواست اتصال به کارشناس (فهرست عبارت‌ها قابل تنظیم) |
| ۷ | مهمانی که نام/موبایلش معلوم نیست به کارشناس وصل می‌شود | **فرم پیش از گفتگو** درون چت (نام، موبایل، و در صورت تنظیم انتخاب دپارتمان)؛ کاربر واردشده این فرم را نمی‌بیند چون مشخصاتش از حساب پر می‌شود |
| ۸ | کارشناس آنلاین و در ساعات کاری | گفتگو در صف قرار می‌گیرد؛ در حالت **خودکار** به کم‌مشغله‌ترین کارشناس آنلاین همان دپارتمان (با ظرفیت آزاد) سپرده می‌شود؛ در حالت **دستی** کارشناسان از صف می‌پذیرند. نوبت صف به بازدیدکننده نمایش داده می‌شود |
| ۹ | هیچ کارشناسی آنلاین نیست یا خارج از ساعات کاری/تعطیل است | **حالت آفلاین**: پیام آفلاین و ساعات پاسخ‌گویی؛ اگر موبایل بازدیدکننده معلوم نباشد فرم تماس؛ پیامک اختیاری به مدیران. گفتگو در زبانه‌ی «پیام آفلاین» میز کار می‌ماند |
| ۱۰ | گفتگو بیش از مهلت تنظیم‌شده در صف بی‌پاسخ ماند | به حالت آفلاین تبدیل می‌شود (فرم تماس + پیامک مدیران) |
| ۱۱ | کارشناس به پیام آفلاین یا گفتگوی بسته پاسخ می‌دهد | گفتگو به همان کارشناس سپرده و باز می‌شود؛ اگر بازدیدکننده آنلاین نباشد و موبایلش معلوم باشد پیامک «پاسخ داده شد» با پیوند `?chat=open` می‌گیرد (با فاصله‌ی حداقل قابل تنظیم) |
| ۱۲ | گفتگوی زنده | پیام‌ها بلادرنگ؛ «در حال نوشتن» دوطرفه (کارشناس متن در حال تایپ بازدیدکننده را هم می‌بیند — قابل خاموش کردن)؛ تیک ارسال/خوانده شدن؛ ارسال تصویر و PDF؛ شکلک؛ صدای اعلان |
| ۱۳ | یادداشت داخلی | کارشناس یادداشتی می‌نویسد که بازدیدکننده هرگز نمی‌بیند (نه در کانال بلادرنگ و نه در تاریخچه) |
| ۱۴ | پاسخ سریع | در میز کار با «/» و بخشی از میانبر؛ `{{name}}` با نام بازدیدکننده جایگزین می‌شود. پاسخ مشترک (مدیر چت) یا شخصی (هر کارشناس) |
| ۱۵ | انتقال گفتگو | به کارشناس دیگر (با یادداشت) یا به صف یک دپارتمان؛ پیام «گفتگو به … منتقل شد» برای بازدیدکننده |
| ۱۶ | ناظر (`livechat.view_all`) | همه‌ی گفتگوها را می‌بیند، می‌تواند وارد گفتگوی کارشناس دیگر شود، منتقل کند یا ببندد |
| ۱۷ | بستن گفتگو (کارشناس، بازدیدکننده یا خودکار پس از بی‌فعالیتی) | پیام پایان؛ اگر کارشناسی پاسخ داده بود، درخواست امتیاز ۱ تا ۵ ستاره و نظر. گفتگوی صفی که بدون پاسخ بسته شود «از دست‌رفته» ثبت می‌شود |
| ۱۸ | پیام خودکار (پیشگام) | مثلاً پس از ۲۰ ثانیه در صفحه‌ی خرید شمش: «سوالی درباره‌ی خرید شمش دارید؟» به‌صورت حباب کنار دکمه یا با باز کردن پنجره؛ در هر نشست مرورگر یک‌بار؛ پاسخ بازدیدکننده گفتگو را با همین پیام آغاز می‌کند |
| ۱۹ | بازدیدکنندگان آنلاین | میز کار فهرست بازدیدکنندگان متصل و صفحه‌ی فعلی هرکدام را نشان می‌دهد؛ کارشناس می‌تواند گفتگو را خودش آغاز کند (پنجره‌ی چت بازدیدکننده باز می‌شود) |
| ۲۰ | ورود/خروج کاربر | گفتگوی مهمان پس از ورود به حساب کاربر متصل می‌شود؛ پس از خروج، همان مرورگر گفتگوی کاربر را **نمی‌بیند** (بازدیدکننده‌ی مهمان جدید). کاربر از هر دستگاهی تاریخچه‌ی خودش را می‌بیند |
| ۲۱ | مسدود کردن | کارشناس بازدیدکننده را مسدود می‌کند (گفتگوهای باز بسته و اتصال قطع می‌شود)؛ مسدودی IP هم از تنظیمات |
| ۲۲ | باز کردن چت از هر جای اپ | `window.dispatchEvent(new Event("arkan-livechat:open"))` یا افزودن `?chat=open` به نشانی صفحه |
| ۲۳ | خاموش کردن کامل | «تنظیمات چت ← چت آنلاین در اپ فعال است» |

## ۲. محتوای پیش‌فرض

در اولین اجرا (وقتی هنوز تنظیماتی ذخیره نشده) منوی زیر و دو دپارتمان «پشتیبانی عمومی» و «واحد مالی» ساخته می‌شود؛ متن همه‌ی پاسخ‌ها از «پنل ← چت آنلاین ← منوی ربات و پاسخ‌های آماده» قابل ویرایش است:

```
در چه موردی سوال دارید؟
├─ 📝 چگونه در آرکان گلد ثبت نام کنیم؟        (پاسخ)
├─ 🕘 اطلاع از ساعات کاری                       (پاسخ با {{working_hours}})
├─ 💳 گفتگو با کارشناس مالی                     (اتصال به کارشناس ← واحد مالی)
├─ 📦 تحویل فیزیکی شمش طلا                      (پاسخ)
│   └─ ثبت درخواست تحویل فیزیکی                (پیوند /dashboard/wallet/physical-delivery)
├─ 🚚 نحوه ارسال شمش های طلا                    (پاسخ)
├─ 💰 نحوه فروش شمش طلا به آرکان گلد            (پاسخ)
├─ 🔍 اصالت سنجی شمش طلا                        (پاسخ)
│   └─ ورود به صفحه‌ی استعلام اصالت             (پیوند /verify)
└─ 💬 سایر موارد                                (اتصال به کارشناس ← پشتیبانی عمومی)
```

پایگاه دانش هم با چند پرسش نمونه (قیمت لحظه‌ای طلا، فراموشی رمز، نیامدن کد تأیید) آغاز می‌شود.

## ۳. حالت هوشمند

پردازش کاملاً روی سرور خود آرکان گلد است و گفتگوی مشتریان به هیچ سرویس بیرونی ارسال نمی‌شود:

- **یکسان‌سازی متن فارسی**: ی/ك عربی، ارقام فارسی و عربی، اعراب و تطویل، نیم‌فاصله (`شمش‌ها` = `شمشها`، `اصالت‌سنجی` = `اصالت سنجی`، `می‌خواهم` = `میخواهم`)، حذف کلمات پرتکرار بی‌معنا و پسوندهای رایج.
- **امتیاز تطبیق** (۰ تا ۱): پوشش دوطرفه‌ی واژه‌های پرسش و مرجع، با پذیرش غلط تایپی یک‌حرفی و پیشوند مشترک؛ کلمات کلیدی چندواژه‌ای وزن جدا دارند.
- **آستانه‌ها**: «حداقل اطمینان برای پاسخ مستقیم» و «حداقل اطمینان برای پیشنهاد» در تنظیمات؛ اگر دو پاسخ تقریباً هم‌امتیاز باشند پیشنهاد داده می‌شود نه حدس.
- **بهبود مداوم**: پرسش‌های بی‌پاسخ با شمارش تکرار در «پایگاه دانش ← پرسش‌های بی‌پاسخ» جمع می‌شوند و با یک کلیک به پرسش و پاسخ تبدیل می‌شوند؛ آمار «مفید بود/نبود» هر پاسخ ثبت می‌شود؛ «آزمایش ربات» نتیجه‌ی هر پرسش را پیش از انتشار نشان می‌دهد.
- **وصل کردن مدل زبانی**: `LivechatSmartService.find` تنها نقطه‌ی تصمیم است؛ اگر بعداً سرویس مدل زبانی در دسترس سرور قرار گرفت، می‌توان آن را همین‌جا پس از پایگاه دانش اضافه کرد.

## ۴. معماری

```
اپ (Next.js)                                   API (NestJS)                              پنل (Next.js)
LiveChatWidget ──BFF /api/livechat/*──────────▶ /livechat/session|messages|upload|...
  (کوکی دسترسی کاربر اضافه می‌شود)               LivechatPublicController
      │                                                 │
      └──Socket.IO wss://api/livechat ─────────▶ LivechatGateway ◀──Socket.IO (بلیت یک‌بارمصرف)── میز کار
          auth: visitorToken                       │      ▲                                   │
                                                   ▼      │ رویدادها                           │ REST /api/admin/livechat/*
                                            LivechatService (موتور گفتگو) ◀── LivechatAdminController (RBAC + ممیزی)
                                            ├ LivechatBotService (منو)
                                            ├ LivechatSmartService (پایگاه دانش)
                                            ├ LivechatSettingsService (تنظیمات + ساعات کاری تهران)
                                            ├ LivechatRealtimeService (حضور و اتاق‌ها)
                                            ├ LivechatStorageService (S3 خصوصی / دیسک)
                                            └ LivechatCronService (هر ۳۰ ثانیه: صف، آفلاین، بستن خودکار)
```

- **احراز هویت بازدیدکننده**: توکن تصادفی ۲۵۶ بیتی در مرورگر؛ فقط هش SHA-256 آن در `livechat_visitor_sessions`. هر بازدیدکننده می‌تواند چند توکن (دستگاه) داشته باشد.
- **احراز هویت کارشناس**: توکن نشست پنل هرگز به مرورگر/سوکت نمی‌رسد؛ برای هر اتصال یک بلیت ۶۰ ثانیه‌ای یک‌بارمصرف از REST پنل (`POST /admin/livechat/socket-ticket`) در Redis صادر می‌شود. همه‌ی تغییرات کارشناس (ارسال، پذیرش، انتقال، بستن، مسدودسازی) از REST پنل با گارد دسترسی و ممیزی انجام می‌شود؛ سوکت فقط برای دریافت رویدادها و «در حال نوشتن» است. نشست پنل هر دقیقه بازبینی و با انقضا، ابطال یا قفل عدم فعالیت، اتصال قطع می‌شود.
- **اتاق‌ها**: `visitor:{id}`، `ops` (همه‌ی کارشناسان؛ فقط صف را کامل می‌بینند)، `ops:all` (ناظران)، `op:{id}` (کارشناس مسئول). یادداشت داخلی فقط به اتاق‌های کارشناسان ارسال می‌شود.
- **پیام تکراری**: هر پیام `clientMessageId` دارد (یکتا در هر گفتگو)؛ ارسال مجدد پس از قطعی شبکه پیام تکراری نمی‌سازد.
- **رقابت دو کارشناس** برای پذیرش یک گفتگو با به‌روزرسانی شرطی حل می‌شود.
- **پیوست‌ها**: پویش ضدبدافزار و پاک‌سازی (`CHAT_ATTACHMENT_POLICY`: jpg/png/webp/pdf تا ۵ مگابایت، بازسازی تصویر)، ذخیره در باکت خصوصی S3 (در نبود S3، `uploads/livechat` بدون مسیر عمومی)؛ دریافت فقط از مسیر احرازشده و نمایش تصویر به‌صورت blob.
- **مقیاس**: حضور در حافظه‌ی همان فرآیند API نگه داشته می‌شود (API یک نمونه دارد). برای اجرای چند نمونه باید adapter ردیس Socket.IO و نگهداری حضور در Redis اضافه شود.

## ۵. مدل داده (`20261028090000_livechat`)

|------|--------|

## ۷. استقرار

- متغیر محیطی جدیدی لازم نیست. ویجت به `NEXT_PUBLIC_NEST_ORIGIN` (پیش‌فرض `https://api.arkan.gold`) از مسیر `/socket.io` وصل می‌شود؛ CSP اپ و پنل نسخه‌ی `wss://` همان دامنه‌ی API را مجاز می‌کند و دامنه‌های گفتینو حذف شده‌اند.
- اگر جلوی API شبکه‌ی توزیع محتوا (CDN) است، WebSocket باید روی آن فعال باشد؛ در غیر این صورت Socket.IO خودکار به long-polling برمی‌گردد (کارکرد کامل، با تأخیر کمی بیشتر).
- پیوست‌ها از همان تنظیمات S3 پیوست تیکت (`S3_*`) استفاده می‌کنند.
- پیامک‌ها از مرکز پیامک موجود ارسال و در `sms_logs` ثبت می‌شوند.

## ۸. آزمون

```bash
cd api && npx jest livechat
INTEGRATION_DATABASE_URL=postgresql://... npx jest livechat.integration
```

آزمون یکپارچه سناریوی منوی ربات، حالت هوشمند با قیمت لحظه‌ای، پیام تکراری، فرم پیش از گفتگو، تخصیص خودکار، پاسخ و پیامک، یادداشت داخلی، بستن و امتیاز، حالت آفلاین و پیامک مدیران، و جداسازی گفتگوی کاربر واردشده از توکن مهمان را روی PostgreSQL واقعی اجرا می‌کند.
