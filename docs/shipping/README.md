# آدرس مشتری، روش ارسال و تعرفه‌ها

این سند سناریوی کامل «دفترچه‌ی آدرس ← انتخاب آدرس هنگام سفارش ← روش و هزینه‌ی ارسال بر اساس منطقه ← پس‌کرایه» و نحوه‌ی پیاده‌سازی آن را شرح می‌دهد.

## ۱. سناریوها

| # | سناریو | رفتار |
|---|--------|-------|
| ۱ | مشتری آدرس‌هایش را در بخش «آدرس‌های من» (`/dashboard/addresses`) ثبت می‌کند | استان از فهرست ۳۱ استان، شهر (با پیشنهاد شهرهای استان)، نشانی، پلاک، واحد، کد پستی ۱۰ رقمی، نام و موبایل تحویل‌گیرنده. حداکثر ۱۰ آدرس؛ یکی پیش‌فرض |
| ۲ | ویرایش/حذف آدرس | سفارش‌ها snapshot نشانی را نگه می‌دارند، پس ویرایش آدرس سابقه را تغییر نمی‌دهد. حذف «نرم» است (`deletedAt`)؛ اگر آدرس پیش‌فرض حذف شود جدیدترین آدرس پیش‌فرض می‌شود |
| ۳ | ثبت سفارش، مرحله‌ی آدرس | آدرس‌های کاربر نمایش داده می‌شوند (پیش‌فرض از قبل انتخاب شده) و امکان افزودن آدرس جدید در همان صفحه هست. با انتخاب آدرس، روش‌های ارسال همان منطقه و هزینه‌ی هرکدام نمایش داده می‌شود |
| ۴ | آدرس در **شهر تهران** (دفتر مرکزی) | پیک اختصاصی، پست عادی (سفارشی)، پست پیشتاز، پست خصوصی (تیپاکس)، تحویل حضوری در دفتر |
| ۵ | آدرس در **سایر شهرهای استان تهران** (مثلاً ورامین) | پست/تیپاکس با تعرفه‌ی درون‌استانی و تحویل حضوری؛ پیک نه |
| ۶ | آدرس در **استان‌های دیگر** (مثلاً شیراز) | پست عادی/پیشتاز و تیپاکس با تعرفه‌ی «سایر استان‌ها» (برون‌استانی) و هزینه‌ی برآوردشده بر اساس وزن و ارزش مرسوله؛ تحویل حضوری |
| ۷ | **پس‌کرایه** فعال برای یک روش در یک منطقه | هزینه‌ی ارسال در مبلغ سفارش **صفر** است؛ برآورد هزینه به مشتری، در جزئیات سفارش، فاکتور و برچسب ارسال نمایش داده می‌شود و مشتری هنگام تحویل به مأمور پست/حمل می‌پردازد |
| ۸ | پس‌کرایه با **انتخاب مشتری** | مشتری بین «پرداخت همراه سفارش» و «پس‌کرایه» انتخاب می‌کند |
| ۹ | **ارسال رایگان** بالای آستانه | اگر جمع اقلام (پیش از کد تخفیف) به آستانه‌ی تعرفه برسد، هزینه بخشیده و «هدیه‌ی خرید» نمایش داده می‌شود (در فاکتور: مبلغ تعرفه + تخفیف برابر) |
| ۱۰ | آدرس بدون کد پستی | روش‌های «نیازمند کد پستی» (پست) غیرقابل انتخاب با پیام «کد پستی را تکمیل کنید» |
| ۱۱ | سقف وزن/ارزش | اگر وزن یا ارزش سفارش از سقف تعرفه بیشتر باشد (مثلاً سقف غرامت پست برای طلا)، آن روش با دلیل غیرقابل انتخاب است |
| ۱۲ | روشی برای آدرس تعریف نشده | پیام «برای این آدرس روش ارسالی تعریف نشده است» و ثبت سفارش مسدود می‌شود |
| ۱۳ | تغییر تعرفه بین برآورد و ثبت سفارش | هزینه در سرور هنگام ثبت سفارش دوباره محاسبه می‌شود؛ به مبلغ ارسالی کلاینت اعتماد نمی‌شود |
| ۱۴ | لغو سفارش پرداخت‌شده | هزینه‌ی ارسال همراه مبلغ سفارش به کیف پول برمی‌گردد و سند درآمد ارسال برگشت می‌خورد |
| ۱۵ | ارسال توسط پنل | روش انتخابی مشتری در فرم «ثبت ارسال» از پیش انتخاب شده است؛ ادمین می‌تواند روش دیگری انتخاب کند (هشدار + ثبت در Timeline) |
| ۱۶ | تحویل فیزیکی طلای آب‌شده (خرید شمش) | همان انتخاب آدرس و روش ارسال؛ هزینه‌ی ارسال پیش‌پرداخت به مابه‌التفاوت افزوده و از طلای اضافه/کیف ریالی/درگاه پرداخت می‌شود |
| ۱۷ | خاموش کردن کل قابلیت | `shop.shipping.enabled = false`: رفتار قبلی (بدون انتخاب روش و هزینه؛ روش فقط هنگام ارسال در پنل) |

## ۲. مدل داده

- **`addresses`**: `province_code` (کد استاندارد استان)، `plaque`، `unit`، `deleted_at`، `updated_at`. کد استان آدرس‌های قدیمی (استان متنی) در مهاجرت و هنگام اجرا از روی نام تشخیص داده می‌شود.
- **`shipping_carriers`**: شرکت‌های حمل (پست، تیپاکس، چاپار، پیک اختصاصی) با تلفن، وب‌سایت و نشانی رهگیری پیش‌فرض.
- **`shipping_methods`** (موجود، توسعه‌یافته): `carrier_id`، `available_at_checkout` (قابل انتخاب مشتری)، `requires_postal_code`، `pickup_address`، `pickup_hours`.
- **`shipping_zones`**: نام، `province_codes[]` (خالی = همه‌ی استان‌ها)، `cities[]` (خالی = همه‌ی شهرهای آن استان‌ها)، اولویت.
- **`shipping_rates`**: تعرفه‌ی یک روش در یک منطقه (یکتا بر `method_id + zone_id`).
- **`shop_orders`**: `shipping_method_id` و snapshot نام/نوع/شرکت/منطقه، `shipping_rial` (دریافتی)، `shipping_waived_rial` (رایگان‌شده)، `shipping_pay_on_delivery`، `shipping_estimate_rial`، `shipment_weight_grams`، زمان تحویل و `shipping_address` (snapshot نشانی).

## ۳. انتخاب منطقه و تعرفه

1. منطقه‌های فعالِ منطبق با آدرس به ترتیب دقت مرتب می‌شوند: **فهرست شهر (۳) › استان (۲) › سایر نقاط کشور (۱)**؛ در تساوی، اولویت کمتر مقدم است.
2. برای هر روشِ فعال و «قابل انتخاب مشتری»، تعرفه‌ی **دقیق‌ترین** منطقه‌ای که برای آن روش تعرفه دارد ملاک است.
3. **تعرفه‌ی غیرفعال** در منطقه‌ی دقیق‌تر یعنی «این روش برای این ناحیه ارائه نمی‌شود» و به تعرفه‌ی کلی‌تر برنمی‌گردد (مثلاً پست را فقط برای شهر تهران خاموش کرد).
4. روش متعلق به شرکت حمل غیرفعال عرضه نمی‌شود.

مناطق پیش‌فرض (مبدأ: دفتر تهران) که فقط یک‌بار و وقتی هیچ منطقه‌ای وجود ندارد ساخته می‌شوند:

| منطقه | استان/شهر | روش‌ها |
|-------|-----------|--------|
| شهر تهران | TEHRAN / تهران | پیک اختصاصی (+ پست/تیپاکس/حضوری از مناطق کلی‌تر) |
| استان تهران | TEHRAN | پست سفارشی، پست پیشتاز، تیپاکس |
| استان‌های همجوار | البرز، قم، مرکزی، سمنان، مازندران | پست سفارشی، پست پیشتاز |
| سایر استان‌ها | همه | پست سفارشی، پست پیشتاز، تیپاکس (پس‌کرایه به انتخاب مشتری)، تحویل حضوری |

> مبالغ تعرفه‌های پیش‌فرض نمونه‌اند و باید از پنل با نرخ روز به‌روز شوند.

## ۴. فرمول هزینه

```
وزن مرسوله  = Σ(وزن هر قلم × تعداد) + shop.shipping.parcel_tare_grams
هزینه       = پایه + ⌈max(0, وزن − وزن پایه) ÷ اندازه‌ی پله⌉ × مبلغ پله + ارزش اقلام × درصد بیمه ÷ ۱۰۰
هزینه       = clamp(هزینه, حداقل, حداکثر)  ← گرد به بالا تا مضرب shop.shipping.round_up_rial
رایگان       اگر ارزش اقلام ≥ آستانه‌ی ارسال رایگان
دریافتی در سفارش:
  رایگان                         → ۰ (بخشیده = هزینه)
  پیش‌پرداخت                     → هزینه
  پس‌کرایه / انتخاب مشتری=پس‌کرایه → ۰ (برآورد = هزینه، پرداخت هنگام تحویل)
```

ارزش اقلام = جمع قیمت‌های قفل‌شده‌ی سبد **پیش از کد تخفیف**. هزینه‌ی ارسال مثل بسته‌بندی مشمول کد تخفیف نیست:

```
totalRial = subtotalRial − discountRial + packagingRial + shippingRial
```

## ۵. حسابداری و فاکتور

- حساب جدید **4035 — درآمد خدمات ارسال سفارش‌های فروشگاه**. سند فروش: بستانکار 4035 به اندازه‌ی `shippingRial` (پس‌کرایه = بدون سطر).
- لغو سفارش پرداخت‌شده: بدهکار 4035 و بازگشت کل مبلغ (شامل ارسال) به کیف پول.
- فاکتور: ردیف «هزینه ارسال — {روش}» با کد `SHIP`؛ ارسال رایگان با مبلغ تعرفه و تخفیف برابر. در پس‌کرایه، توضیح «پس‌کرایه — حدود X ریال هنگام تحویل» در بخش توضیحات فاکتور.
- برچسب ارسال: نشانی snapshot (با پلاک/واحد)، روش انتخابی مشتری پیش از ثبت ارسال و فیلد جدید `{{shipping.payment}}` (پس‌کرایه/پیش‌کرایه).

## ۶. پنل مدیریت

- **فروشگاه › مراجع ارسال**: شرکت حمل، «قابل انتخاب مشتری»، «فقط با کد پستی»، نشانی و ساعات تحویل حضوری.
- **فروشگاه › مناطق و تعرفه‌های ارسال**:
  - *تعرفه‌ها*: ماتریس روش × منطقه؛ هر خانه = تعرفه (پایه، پله‌ی وزنی، بیمه، حداقل/حداکثر، ارسال رایگان، سقف وزن/ارزش، زمان تحویل، نحوه‌ی پرداخت: پیش‌پرداخت / پس‌کرایه / انتخاب مشتری، فعال/«ارائه نمی‌شود»).
  - *مناطق*: انتخاب استان‌ها و (اختیاری) شهرها.
  - *شرکت‌های حمل*.
  - *شبیه‌ساز هزینه*: استان، شهر، کد پستی، وزن و ارزش ← گزینه‌ها، منطقه‌ی ملاک، هزینه و وضعیت هر روش.
- **تنظیمات سیستم › فروشگاه › ارسال سفارش و تعرفه‌ها**: `shop.shipping.enabled`، `shop.shipping.parcel_tare_grams`، `shop.shipping.round_up_rial`.
- **سفارشات فروشگاه**: روش انتخابی مشتری، منطقه، وزن، هزینه یا پس‌کرایه؛ پیش‌انتخاب همان روش در فرم «ثبت ارسال».

دسترسی‌ها: مشاهده `shop.view`، تغییر `shop.manage` (همه‌ی تغییرات در Audit Log).

## ۸. آزمون‌ها

- `api/src/shipping/shipping-calculator.spec.ts`: تطبیق منطقه، فرمول هزینه، پس‌کرایه، رایگان، سقف‌ها و کد پستی.
- `api/src/shipping/shipping.integration.spec.ts` (روی PostgreSQL واقعی): دفترچه‌ی آدرس، گزینه‌های تهران/شیراز، ثبت سفارش با هزینه‌ی ارسال، سند 4035 و ردیف فاکتور، برگشت هنگام لغو، پس‌کرایه، ارسال رایگان و خاموش کردن قابلیت.

```bash
INTEGRATION_DATABASE_URL=postgresql://... npx jest shipping
```

## ۹. توسعه‌های بعدی پیشنهادی

- اتصال به API رسمی پست/تیپاکس برای استعلام لحظه‌ای نرخ و صدور بارکد پستی.
- مناطق درون‌شهری پیک (مناطق شهرداری یا فاصله با نقشه).
- انتخاب بازه‌ی زمانی تحویل برای پیک و ساعت مراجعه‌ی حضوری.
