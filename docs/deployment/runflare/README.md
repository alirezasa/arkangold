# استقرار آرکان گلد روی رانفلر (کنار لیارا)

پروژه روی هر دو پلتفرم قابل استقرار است و کد یکسانی دارد:

| | لیارا | رانفلر |
| --- | --- | --- |
| روش استقرار | GitHub Actions با `liara deploy` ([راهنما](../liara/README.md)) | اتصال مستقیم سرویس به مخزن گیت‌هاب (گیت‌هاب کلاسیک) و دریافت خودکار |
| زمان استقرار | هر push به `main` (فقط سرویس‌های تغییرکرده) | هر push به برنچ متصل (هر سه سرویس) |
| پیکربندی | `liara.*.json`، `.liaraignore` | تنظیمات سرویس در پنل رانفلر |

سه سرویس Node.js در **یک پروژه‌ی** رانفلر، هر کدام با دامنه‌ی خودش:

| سرویس (نام پیشنهادی) | دامنه | `APP_SERVICE` | فایل متغیرها |
| --- | --- | --- | --- |
| `arkan-api` | `api.arkan.gold` | `api` | [`api.env.example`](./api.env.example) |
| `arkan-app` | `app.arkan.gold` | `app` | [`app.env.example`](./app.env.example) |
| `arkan-admin` | `admin.arkan.gold` | `admin` | [`admin.env.example`](./admin.env.example) |

## ساختار استقرار

هر سه سرویس به **همان مخزن و همان برنچ** وصل می‌شوند و کل مونوریپو را دریافت می‌کنند؛ فقط متغیر محیطی
`APP_SERVICE` تعیین می‌کند کدام بسته ساخته و اجرا شود. رانفلر برای Node.js به‌ترتیب `npm install`،
`npm run build` و `npm start` را در ریشه اجرا می‌کند؛ این دو اسکریپت در `package.json` ریشه به
`scripts/deploy/run.mjs` سپرده شده‌اند (همان روند لیارا):

- `build`: نصب وابستگی‌های همان سرویس با pnpm و build (برای api: پکیج shared، `prisma generate`،
  `nest build`؛ برای app/admin: `next build`). اگر `APP_SERVICE` در زمان build در دسترس نباشد هر سه
  سرویس ساخته می‌شوند و در زمان اجرا همان یکی بالا می‌آید.
- `start`: برای api ابتدا `prisma migrate deploy` (با `PRISMA_MIGRATE_ON_START=false` غیرفعال می‌شود)، بعد
  اجرای سرور روی `PORT` (پیش‌فرض 3000).

## راه‌اندازی رانفلر (مرحله به مرحله)

### ۱. پروژه و دیتابیس‌ها

1. در [پنل رانفلر](https://portal.runflare.com/) یک پروژه بسازید (مثلاً `arkan`).
2. در همین پروژه یک **PostgreSQL** بسازید. نسخه‌ی اصلی (major) آن برابر یا بالاتر از PostgreSQL لیارا باشد
   (نسخه‌ی لیارا را در صفحه‌ی دیتابیس لیارا ببینید).
3. یک **Redis** هم بسازید.
4. اطلاعات اتصال هر دو را از صفحه‌ی هر دیتابیس بردارید (آدرس داخلی برای سرویس‌ها).

### ۲. سه سرویس Node.js

برای هر کدام از `arkan-api`، `arkan-app` و `arkan-admin`
([ایجاد برنامه NodeJS](https://docs.runflare.com/nodejs/nodejs-create-app/)):

- نسخه‌ی Node.js: **22** (pnpm 11 به Node 22.13 به بالا نیاز دارد)
- پورت: **3000**

### ۳. دیسک سرویس api

تصاویر محصولات، طرح‌های بسته‌بندی و مدارک حقوقی روی دیسک در `api/uploads` ذخیره می‌شوند و بدون دیسک با هر
استقرار پاک می‌شوند. طبق [ساخت دیسک جدید](https://docs.runflare.com/nodejs/nodejs-add-disk/) یک دیسک برای
سرویس `arkan-api` با مسیر **`api/uploads`** درون پوشه‌ی برنامه بسازید. اگر پنل مسیر مطلق می‌خواهد، در
کنسول سرویس `pwd` بزنید و `/api/uploads` را به آن اضافه کنید.

### ۴. متغیرهای محیطی

طبق [تنظیم متغیر محیطی](https://docs.runflare.com/nodejs/nodejs-environment-variables/)، فایل‌های
`*.env.example` همین پوشه را کامل کنید و در هر سرویس وارد کنید:

- **مقادیر را از برنامه‌های لیارا کپی کنید.** فقط `DATABASE_URL` و `REDIS_*` سرویس api به دیتابیس‌های
  رانفلر تغییر می‌کند.
- **`INTEGRATION_ENCRYPTION_KEY` و همه‌ی `JWT_*` باید دقیقاً همان مقادیر لیارا باشند**؛ وگرنه داده‌های
  رمزنگاری‌شده‌ی دیتابیس خوانده نمی‌شوند و همه‌ی کاربران از حساب خارج می‌شوند.
- `S3_*` را همان مقادیر لیارا بگذارید (رسیدها و پیوست تیکت‌ها در همان باکت لیارا می‌مانند و از رانفلر هم
  در دسترس‌اند). جابه‌جایی باکت اختیاری است (پایین‌تر).
- **تا پایان انتقال دیتابیس** در `arkan-api` مقدار `PRISMA_MIGRATE_ON_START=false` بگذارید تا API روی
  دیتابیس خالی جدول نسازد.
- متغیرهای `NEXT_PUBLIC_*` هنگام build در کد قرار می‌گیرند؛ اول متغیرها را ذخیره کنید، بعد استقرار کنید.

### ۵. اتصال به گیت‌هاب (گیت‌هاب کلاسیک) و استقرار

طبق [استقرار NodeJS با Github](https://docs.runflare.com/nodejs/nodejs-deploy-github/#githubclassic):

1. **توکن گیت‌هاب**: GitHub ← Settings ← Developer settings ← Personal access tokens ← **Tokens (classic)**
   ← Generate new token (classic). در Note یک نام (مثلاً `runflare-arkan`) بنویسید، فقط دسترسی **`repo`**
   را تیک بزنید، تاریخ انقضا را مشخص کنید و Generate را بزنید. توکن را کپی کنید (فقط یک بار نمایش داده
   می‌شود).
2. **آدرس مخزن**: در صفحه‌ی مخزن، Code ← HTTPS:
   ```
   https://github.com/alirezasa/arkangold.git
   ```
3. در رانفلر ← مدیریت پروژه ← پروژه‌ی `arkan` ← تنظیمات سرویس `arkan-api` ← **اتصال به مخزن گیت** ←
   **گیت هاب کلاسیک**: آدرس مخزن، برنچ **`main`** و توکن را وارد و ذخیره کنید.
4. در فهرست commitها جلوی آخرین commit روی **Revert** بزنید تا استقرار شروع شود. لاگ را در صفحه‌ی سرویس
   ← **سابقه‌ی استقرار** ببینید (خطوط اسکریپت با `[deploy]` شروع می‌شوند).
5. تیک **دریافت خودکار** را بزنید تا با هر push به `main` سرویس خودش به‌روز شود.
6. همین چهار قدم را برای `arkan-app` و `arkan-admin` تکرار کنید (همان مخزن، همان برنچ، همان توکن).

> با انقضای توکن، دریافت خودکار از کار می‌افتد. پیش از انقضا توکن جدید بسازید و در هر سه سرویس جایگزین کنید.

### ۶. آزمایش با دامنه‌ی موقت

پیش از جابه‌جایی دامنه‌ها، با [دامنه‌ی موقت](https://docs.runflare.com/general/temporary-domain/) مطمئن شوید
هر سه سرویس بالا آمده‌اند (api در این مرحله هنوز دیتابیس خالی دارد و طبیعی است که خطای دیتابیس بدهد).

## انتقال اطلاعات از لیارا به رانفلر

| داده | کجاست | روش انتقال |
| --- | --- | --- |
| دیتابیس PostgreSQL | دیتابیس لیارا | `scripts/migrate/db.sh` (dump و restore کامل + مقایسه‌ی تعداد ردیف‌ها) |
| فایل‌های آپلودشده (`api/uploads`) | دیسک `uploads` لیارا | `scripts/migrate/files.mjs`: `push` روی لیارا ← باکت S3 ← `pull` روی رانفلر |
| رسیدهای واریز و پیوست تیکت‌ها | باکت S3 لیارا | منتقل نمی‌شوند؛ رانفلر از همان باکت استفاده می‌کند (یا `copy-bucket`) |
| Redis | — | منتقل نمی‌شود؛ فقط داده‌ی موقت دارد (OTP، محدودیت درخواست، قفل‌ها) |

### پیش‌نیازها (یک بار)

1. **اسکریپت انتقال روی لیارا**: این تغییرات باید در `main` باشد و یک بار api لیارا با آن deploy شود. چون
   workflow لیارا فقط سرویس‌های تغییرکرده را deploy می‌کند، دستی اجرا کنید: گیت‌هاب ← **Actions ← Deploy to
   Liara ← Run workflow** با مقدار `api`.
2. **دسترسی عمومی دیتابیس‌ها**: در پنل لیارا (دیتابیس ← تنظیمات شبکه ← دسترسی عمومی) و در رانفلر دسترسی
   عمومی PostgreSQL را موقتاً فعال کنید و آدرس عمومی هر دو را بردارید. اگر رانفلر برای دیتابیس آدرس عمومی
   نمی‌دهد، از پشتیبانی رانفلر بخواهید فایل dump را restore کنند (روش جایگزین در قدم ۴ پایین).
3. **ابزار PostgreSQL روی سیستم خودتان**: `pg_dump`، `pg_restore` و `psql` با نسخه‌ی برابر یا بالاتر از
   دیتابیس‌ها.
   - ویندوز: نصب PostgreSQL از [postgresql.org](https://www.postgresql.org/download/windows/) (فقط
     Command Line Tools کافی است) و اجرای اسکریپت در **Git Bash**. یا دستورهای دستی قدم ۴ را در PowerShell
     بزنید.
   - لینوکس: `sudo apt install postgresql-client`

### روز انتقال (چند دقیقه قطعی)

**۱. توقف نوشتن روی لیارا**: در پنل لیارا برنامه‌های `arkan-app` و `arkan-admin` را خاموش کنید تا کاربران
چیزی ثبت نکنند.

**۲. فایل‌های دیسک لیارا ← باکت**: در کنسول برنامه‌ی `arkan-api` لیارا (پنل ← کنسول، یا
`liara shell --app arkan-api`):

```bash
node scripts/migrate/files.mjs push
```

همه‌ی فایل‌های `api/uploads` با همان متغیرهای `S3_*` برنامه در مسیر `_migration/uploads/` باکت قرار
می‌گیرند. در پایان تعداد و حجم فایل‌ها چاپ می‌شود.

**۳. خاموش کردن api لیارا**: برنامه‌ی `arkan-api` لیارا را خاموش کنید تا کارهای زمان‌بندی‌شده هم دیگر در
دیتابیس ننویسند.

**۴. انتقال دیتابیس**: روی سیستم خودتان در ریشه‌ی پروژه، با آدرس‌های **عمومی** دو دیتابیس:

```bash
SOURCE_DATABASE_URL='postgresql://USER:PASS@LIARA-HOST:PORT/DB' \
TARGET_DATABASE_URL='postgresql://USER:PASS@RUNFLARE-HOST:PORT/DB' \
bash scripts/migrate/db.sh
```

- اسکریپت dump را در پوشه‌ی جاری نگه می‌دارد (`arkan-liara-*.dump`، نسخه‌ی پشتیبان)، روی رانفلر restore
  می‌کند و در پایان **تعداد ردیف‌های همه‌ی جدول‌ها را در دو طرف مقایسه می‌کند**؛ اگر یکسان نباشد خطا می‌دهد.
- اگر گفت دیتابیس مقصد خالی نیست (مثلاً API قبلاً با migrate جدول ساخته)، با `--clean` دوباره اجرا کنید.
- معادل دستی (مثلاً در PowerShell):
  ```powershell
  pg_dump "postgresql://...لیارا..." --format=custom --no-owner --no-privileges --file=arkan.dump
  pg_restore --no-owner --no-privileges --exit-on-error --dbname="postgresql://...رانفلر..." arkan.dump
  ```
  اگر رانفلر آدرس عمومی ندارد، همین `arkan.dump` را برای restore به پشتیبانی رانفلر بدهید.

**۵. باکت ← دیسک رانفلر**: در کنسول سرویس `arkan-api` رانفلر:

```bash
node scripts/migrate/files.mjs pull
```

فایل‌ها در `api/uploads` (دیسک) نوشته می‌شوند. هر دو دستور `push` و `pull` دوباره‌اجراشدنی‌اند و فایل‌های
موجود را دوباره منتقل نمی‌کنند.

**۶. روشن کردن migrate**: در متغیرهای `arkan-api` رانفلر `PRISMA_MIGRATE_ON_START=true` بگذارید و سرویس را
ری‌استارت کنید.

**۷. دامنه‌ها**: دامنه‌های `api.arkan.gold`، `app.arkan.gold` و `admin.arkan.gold` را از برنامه‌های لیارا
حذف و طبق [افزودن دامنه به Nodejs](https://docs.runflare.com/nodejs/nodejs-add-domain/) به سرویس‌های رانفلر
اضافه کنید، رکوردهای DNS (یا مبدأ CDN آروان) را طبق پنل رانفلر عوض کنید و SSL را فعال کنید.

**۸. بررسی**:

- ورود کاربر و ادمین (همان حساب‌ها و بدون خروج از حساب)
- نمایش تصاویر محصولات و طرح‌های بسته‌بندی
- باز شدن مدارک حقوقی، رسیدهای واریز و پیوست تیکت‌ها
- یک پرداخت آزمایشی: `payment.gateway.callback_base_url` همراه دیتابیس منتقل شده و باید
  `https://api.arkan.gold` باشد

### بعد از انتقال

- دسترسی عمومی هر دو دیتابیس را خاموش کنید.
- برنامه‌ها و دیتابیس لیارا را تا مطمئن شدن از رانفلر **خاموش نگه دارید و پاک نکنید** (بازگشت سریع: روشن
  کردن برنامه‌های لیارا و برگرداندن DNS).
- پوشه‌ی `_migration/` را از باکت پاک کنید.
- کاربری که وسط انتقال کد OTP گرفته باید دوباره درخواست کند (Redis منتقل نمی‌شود).
- اگر لیارا را فقط پشتیبان نگه می‌دارید، استقرار خودکارش با هر push ادامه دارد؛ برای توقف، بخش `push` را در
  `.github/workflows/deploy-liara.yml` حذف کنید تا فقط دستی اجرا شود.

### جابه‌جایی باکت S3 (اختیاری)

اگر رسیدها و پیوست‌ها را هم به باکت دیگری می‌برید: باکت جدید را بسازید، `S3_*` سرویس `arkan-api` رانفلر را
به آن تغییر دهید و در کنسول همان سرویس:

```bash
SRC_S3_ENDPOINT=https://storage.iran.liara.space SRC_S3_BUCKET=... \
SRC_S3_ACCESS_KEY=... SRC_S3_SECRET_KEY=... \
node scripts/migrate/files.mjs copy-bucket
```

در این حالت قدم ۵ بالا را با مقادیر باکت لیارا جلوی دستور اجرا کنید:
`S3_ENDPOINT=... S3_BUCKET=... S3_ACCESS_KEY=... S3_SECRET_KEY=... node scripts/migrate/files.mjs pull`

## نکات

- **`INTERNAL_PROXY_SECRET`** را با یک مقدار یکسان در هر سه سرویس بگذارید تا API، IP و User-Agent واقعی
  کاربر را از سرورهای Next.js بپذیرد.
- **CDN آروان**: رنج‌های IP آروان را در `CDN_PROXY_RANGES` هر سه سرویس بگذارید (توضیح در
  [راهنمای لیارا](../liara/README.md#نکات)).
- **کمبود حافظه در build**: اگر `next build` با خطای heap متوقف شد، `NODE_OPTIONS=--max-old-space-size=2048`
  را اضافه کنید یا منابع سرویس را بیشتر کنید.
- **فایل قفل**: بعد از هر تغییر در وابستگی‌ها `pnpm install` و `pnpm run lockfile:sync` را در ریشه اجرا و هر
  دو فایل قفل را commit کنید.
