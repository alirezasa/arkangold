# استقرار آرکان گلد روی رانفلر

رانفلر محل اصلی استقرار است و با هر push به `main` خودکار deploy می‌شود. لیارا به‌عنوان پشتیبان باقی
مانده و فقط دستی deploy می‌شود ([راهنمای لیارا](../liara/README.md)).

سه سرویس Node.js در **یک پروژه‌ی** رانفلر، هر کدام با دامنه‌ی خودش:

| سرویس (نام پیشنهادی) | دامنه | `APP_SERVICE` | فایل متغیرها |
| --- | --- | --- | --- |
| `arkan-api` | `api.arkan.gold` | `api` | [`api.env.example`](./api.env.example) |
| `arkan-app` | `app.arkan.gold` | `app` | [`app.env.example`](./app.env.example) |
| `arkan-admin` | `admin.arkan.gold` | `admin` | [`admin.env.example`](./admin.env.example) |

## ساختار استقرار

هر سه سرویس کل مونوریپو را دریافت می‌کنند و `APP_SERVICE` تعیین می‌کند کدام بسته ساخته و اجرا شود.
رانفلر برای Node.js به‌ترتیب `npm install`، `npm run build` و `npm start` را در ریشه اجرا می‌کند؛ این دو
اسکریپت در `package.json` ریشه به `scripts/deploy/run.mjs` سپرده شده‌اند (همان روند لیارا):

- `build`: نصب وابستگی‌های همان سرویس با pnpm، و build (برای api: پکیج shared، `prisma generate`،
  `nest build`؛ برای app/admin: `next build`)
- `start`: برای api ابتدا `prisma migrate deploy` (با `PRISMA_MIGRATE_ON_START=false` غیرفعال می‌شود)، بعد
  اجرای سرور روی `PORT` (پیش‌فرض 3000)

CLI رانفلر فایل‌ها را بر اساس **`.gitignore` ریشه** انتخاب می‌کند (`node_modules`، خروجی‌های build و
فایل‌های `.env` آپلود نمی‌شوند) و فقط فایل‌های تغییرکرده را می‌فرستد. وضعیت محلی CLI در پوشه‌ی `.cloud`
ذخیره می‌شود که در `.gitignore` است.

## راه‌اندازی در پنل رانفلر (یک بار)

1. **پروژه**: یک پروژه بسازید (مثلاً `arkan`). نام (namespace) آن را برای GitHub Actions لازم دارید.
2. **دیتابیس‌ها**: در همین پروژه یک **PostgreSQL** (نسخه‌ی اصلی برابر یا بالاتر از دیتابیس لیارا) و یک
   **Redis** بسازید و اطلاعات اتصال داخلی را بردارید.
3. **سه سرویس Node.js** با نام‌های جدول بالا: نسخه‌ی Node **22** (pnpm 11 به Node 22.13 به بالا نیاز دارد)
   و پورت **3000**.
4. **دیسک سرویس api**: پروژه ← دیسک‌ها ← افزودن دیسک، سرویس `arkan-api` و مسیر **`api/uploads`** درون
   پوشه‌ی برنامه. اگر پنل مسیر مطلق می‌خواهد، در کنسول سرویس `pwd` بزنید و `/api/uploads` را به آن اضافه
   کنید. تصاویر محصولات، طرح‌های بسته‌بندی و مدارک حقوقی این‌جا ذخیره می‌شوند و بدون دیسک با هر deploy
   پاک می‌شوند.
5. **متغیرهای محیطی**: فایل‌های `*.env.example` همین پوشه را کامل کنید و در تنظیمات هر سرویس وارد کنید.
   هنگام مهاجرت، مقادیر را از برنامه‌های لیارا کپی کنید (توضیح بالای [`api.env.example`](./api.env.example)).
   متغیرهای `NEXT_PUBLIC_*` هنگام build در کد قرار می‌گیرند؛ اول متغیرها را ذخیره کنید، بعد deploy کنید.

## استقرار

### خودکار با GitHub Actions

workflow [`deploy-runflare.yml`](../../../.github/workflows/deploy-runflare.yml) با هر push به `main`
فقط سرویس‌هایی را deploy می‌کند که فایل‌هایشان تغییر کرده (هم‌زمان، هر کدام در یک job جدا):

| تغییر در | deploy |
| --- | --- |
| `api/`، `packages/`، `scripts/migrate/` | api |
| `app/`، `packages/` | app |
| `admin/` | admin |
| `package.json`، `pnpm-lock.yaml`، `pnpm-workspace.yaml`، `scripts/deploy/`، `.gitignore` | هر سه |

راه‌اندازی در گیت‌هاب: **Settings ← Secrets and variables ← Actions**

| نوع | نام | مقدار |
| --- | --- | --- |
| Secret | `RUNFLARE_EMAIL` | ایمیل حساب رانفلر |
| Secret | `RUNFLARE_PASSWORD` | رمز حساب رانفلر |
| Variable | `RUNFLARE_PROJECT` | نام (namespace) پروژه در رانفلر |
| Variable (اختیاری) | `RUNFLARE_SERVICE_API` / `_APP` / `_ADMIN` | نام سرویس‌ها اگر با `arkan-api` / `arkan-app` / `arkan-admin` فرق دارد |

- workflow با CLI رسمی رانفلر روی PyPI (`runflare`) و با ایمیل و رمز وارد می‌شود. ورود دومرحله‌ای همین حساب
  باید خاموش باشد (CLI در CI نمی‌تواند کد آن را بپرسد). بهتر است برای CI یک حساب جدا با دسترسی به همین
  پروژه بسازید.
- **deploy دستی** (مثلاً بعد از تغییر متغیرها): تب **Actions ← Deploy to Runflare ← Run workflow**.
- workflow پس از آپلود، لاگ build را تا پایان نشان می‌دهد؛ نتیجه‌ی نهایی و لاگ اجرا را در پنل رانفلر ← سرویس
  ← رویدادها و لاگ‌ها هم ببینید.

### دستی از سیستم خودتان

```bash
# نصب CLI: ویندوز با install.bat ریشه‌ی پروژه (Run as Administrator)،
# لینوکس/مک: /bin/bash -c "$(curl -fsSL https://get.runflare.com/install.sh)"
runflare login
runflare deploy        # از ریشه‌ی مونوریپو؛ پروژه و سرویس را انتخاب کنید
runflare deploy -y     # deploy دوباره روی همان سرویس قبلی
runflare logs -f       # لاگ زنده
```

## مهاجرت از لیارا به رانفلر

چه چیزهایی منتقل می‌شوند:

| داده | کجاست | روش انتقال |
| --- | --- | --- |
| دیتابیس PostgreSQL | دیتابیس لیارا | `scripts/migrate/db.sh` (dump و restore کامل و مقایسه‌ی تعداد ردیف‌ها) |
| فایل‌های دیسک (`api/uploads`) | دیسک `uploads` لیارا | `scripts/migrate/files.mjs push` روی لیارا و `pull` روی رانفلر، از طریق باکت S3 |
| رسیدهای واریز و پیوست تیکت‌ها | باکت S3 لیارا | همان باکت را نگه دارید، یا `files.mjs copy-bucket` به باکت جدید |
| متغیرهای محیطی و کلیدها | تنظیمات برنامه‌های لیارا | کپی دستی؛ کلیدها **باید** همان مقادیر قبلی باشند |
| Redis | — | منتقل نمی‌شود: فقط داده‌ی موقت دارد (OTP، محدودیت درخواست، قفل‌ها) |

### ۱. آماده‌سازی (بدون قطعی سایت)

1. این نسخه را یک بار روی **api لیارا** هم deploy کنید تا `scripts/migrate/files.mjs` آن‌جا باشد:
   **Actions ← Deploy to Liara ← Run workflow** با مقدار `api`.
2. منابع رانفلر را طبق «راه‌اندازی در پنل رانفلر» بسازید. در متغیرهای `arkan-api` فعلاً
   **`PRISMA_MIGRATE_ON_START=false`** بگذارید تا API روی دیتابیس خالی جدول نسازد.
3. هر سه سرویس را روی رانفلر deploy کنید و مطمئن شوید build موفق است (هنوز دامنه‌ها روی لیاراست).
4. در پنل لیارا و رانفلر **دسترسی عمومی** هر دو PostgreSQL را موقتاً فعال کنید و روی سیستم خودتان
   `postgresql-client` (نسخه‌ی برابر یا بالاتر از دیتابیس‌ها) نصب کنید.

### ۲. انتقال (چند دقیقه قطعی)

1. **توقف نوشتن روی لیارا**: برنامه‌های `arkan-app` و `arkan-admin` لیارا را خاموش کنید.
2. **فایل‌های دیسک → باکت**: در کنسول برنامه‌ی `arkan-api` لیارا (یا `liara shell --app arkan-api`):
   ```bash
   node scripts/migrate/files.mjs push
   ```
   فایل‌ها با همان متغیرهای `S3_*` برنامه در مسیر `_migration/uploads/` باکت قرار می‌گیرند.
3. برنامه‌ی `arkan-api` لیارا را هم خاموش کنید (cronها دیگر چیزی در دیتابیس ننویسند).
4. **دیتابیس**: روی سیستم خودتان، با آدرس‌های عمومی دو دیتابیس:
   ```bash
   SOURCE_DATABASE_URL='postgresql://...لیارا...' \
   TARGET_DATABASE_URL='postgresql://...رانفلر...' \
   bash scripts/migrate/db.sh
   ```
   اگر دیتابیس رانفلر خالی نیست (مثلاً قبلاً API با migrate روی آن جدول ساخته)، `--clean` اضافه کنید. فایل
   dump در پوشه‌ی جاری می‌ماند (نسخه‌ی پشتیبان)؛ اسکریپت در پایان تعداد ردیف‌های همه‌ی جدول‌ها را مقایسه
   می‌کند و اگر یکسان نباشد خطا می‌دهد.
5. **باکت → دیسک رانفلر**: در کنسول سرویس `arkan-api` رانفلر (متغیرهای `S3_*` آن باید به همان باکتی
   اشاره کنند که در قدم ۲ استفاده شد؛ اگر سرویس به باکت جدیدی وصل است، مقادیر باکت لیارا را جلوی دستور
   بنویسید: `S3_ENDPOINT=... S3_BUCKET=... S3_ACCESS_KEY=... S3_SECRET_KEY=... node ...`):
   ```bash
   node scripts/migrate/files.mjs pull
   ```
6. **باکت جدید (اختیاری)**: اگر رسیدها و پیوست‌ها را هم به باکت دیگری می‌برید، روی همان کنسول رانفلر:
   ```bash
   SRC_S3_ENDPOINT=https://storage.iran.liara.space SRC_S3_BUCKET=... \
   SRC_S3_ACCESS_KEY=... SRC_S3_SECRET_KEY=... \
   node scripts/migrate/files.mjs copy-bucket
   ```
   (`S3_*` سرویس باید از قبل به باکت جدید اشاره کند.) هر سه دستور دوباره‌اجراشدنی‌اند و فایل‌های موجود را
   دوباره منتقل نمی‌کنند.
7. در متغیرهای `arkan-api` رانفلر `PRISMA_MIGRATE_ON_START=true` بگذارید و سرویس را ری‌استارت کنید.
8. **دامنه‌ها**: دامنه‌های `api` / `app` / `admin.arkan.gold` را از برنامه‌های لیارا حذف و به سرویس‌های
   رانفلر اضافه کنید، رکوردهای DNS (یا مبدأ CDN آروان) را طبق پنل رانفلر عوض کنید و SSL را فعال کنید.
9. **بررسی**: ورود کاربر و ادمین، نمایش تصاویر محصولات و طرح‌های بسته‌بندی، باز شدن مدارک حقوقی و رسیدها،
   پیوست تیکت‌ها و بازگشت از درگاه پرداخت (`payment.gateway.callback_base_url` همراه دیتابیس منتقل شده و
   باید `https://api.arkan.gold` باشد).

### ۳. بعد از مهاجرت

- دسترسی عمومی هر دو دیتابیس را خاموش کنید.
- برنامه‌ها و دیتابیس لیارا را تا مطمئن شدن از رانفلر خاموش نگه دارید و پاک نکنید (بازگشت سریع).
- پوشه‌ی `_migration/` را از باکت پاک کنید.
- کدهای OTP و محدودیت‌های درخواست در Redis قدیمی می‌مانند؛ کاربری که وسط مهاجرت کد گرفته باید دوباره
  درخواست کند.

## نکات

- **`INTERNAL_PROXY_SECRET`** را با یک مقدار یکسان در هر سه سرویس بگذارید تا API، IP و User-Agent واقعی
  کاربر را از سرورهای Next.js بپذیرد؛ بدون آن همه‌ی کاربران app/admin یک IP شمرده می‌شوند.
- **CDN آروان**: رنج‌های IP آروان را در `CDN_PROXY_RANGES` هر سه سرویس بگذارید (توضیح در
  [راهنمای لیارا](../liara/README.md#نکات)).
- **کمبود حافظه در build**: اگر `next build` با خطای heap متوقف شد، `NODE_OPTIONS=--max-old-space-size=2048`
  را اضافه کنید یا منابع سرویس را بیشتر کنید.
- **فایل قفل**: بعد از هر تغییر در وابستگی‌ها `pnpm install` و `pnpm run lockfile:sync` را در ریشه اجرا و هر
  دو فایل قفل را commit کنید (کپی فایل قفل برای لیارا لازم است).
- **اجرای محلی**: `APP_SERVICE=api npm run build && APP_SERVICE=api PORT=5000 npm start`
