# حسابداری پیشرفته — دفتر کل، خزانه و خرید پوششی طلا، موجودی شمش و شرکای فروش اقساطی

هدف: همه‌ی عملیات مالی آرکان گلد داخل خود سامانه ثبت، کنترل و گزارش شود تا به نرم‌افزار حسابداری جداگانه نیازی نباشد.
این سند ساختار حساب‌ها، سناریوها، اسناد حسابداری، گزارش‌ها و مراحل راه‌اندازی را شرح می‌دهد.

## ۱. خلاصه‌ی قابلیت‌ها

| حوزه | قابلیت | مسیر پنل |
|---|---|---|
| دفتر کل | سرفصل سلسله‌مراتبی (کل ← معین)، شماره عطف و شماره قطعی اسناد، منبع و مرجع هر سند، سند برگشتی | حسابداری ← سرفصل حساب‌ها / دفتر روزنامه |
| اسناد دستی | هزینه‌ها، اصلاحیه، سند افتتاحیه — با کنترل دوگانه (ثبت ← تأیید شخص دوم ← دفتر کل) | حسابداری ← اسناد دستی و هزینه‌ها |
| گزارش‌ها | داشبورد مالی، تراز چهارستونی دوره‌ای، دفتر معین با مانده جاری، سود و زیان، ترازنامه، موقعیت طلا، مغایرت‌گیری، خروجی اکسل | حسابداری ← … |
| دوره‌ی مالی | سال مالی، قفل دوره، قطعی‌سازی اسناد (شماره دائم بدون فاصله)، بستن حساب‌های موقت | حسابداری ← سال مالی و قفل دوره |

| موجودی شمش | گزارش لحظه‌ای: کد خام، کددار خزانه، نزد نماینده، فروخته، در انتظار کد، موجودی فروشگاه؛ کدگذاری گروهی | خزانه و شمش ← موجودی شمش |
| شرکای فروش | اسنپ‌پی، دیجی‌پی و اپ‌های همکار: قرارداد، کارمزد، سفارش، تسویه، استرداد، سنی مطالبات، API | شرکای فروش (اقساطی) ← … |

## ۲. سرفصل حساب‌ها

ماهیت هر حساب از رقم اول کد تعیین می‌شود: `1` دارایی و `5` هزینه = بدهکار؛ `2` بدهی، `3` حقوق صاحبان سهام و `4` درآمد = بستانکار.
هر سطر سند هم مبلغ ریالی و هم وزن (گرم) دارد و هر سند باید **هم از نظر ریال و هم از نظر گرم** تراز باشد.

واحد گرم: حساب‌های طلای آب‌شده (1020، 1060، 1090، 2020) = **گرم معادل ۷۵۰ (۱۸ عیار)**؛
حساب‌های شمش (1025، 1030، 1095، 5050، 5060) = وزن فیزیکی شمش.

| کد | حساب | توضیح |
|---|---|---|
| 1010 | موجودی نقد و بانک | برای هر بانک/صندوق زیرحساب تعریف کنید (مثلاً 101001) |
| 1020 | طلای آب‌شده خزانه | فقط با خرید/فروش واقعی از بازار، تحویل فیزیکی و شمارش خزانه تغییر می‌کند |
| 1025 | شمش و مسکوکات خزانه | به بهای تمام‌شده (میانگین موزون) |
| 1030 | شمش امانی نزد نمایندگان | کنترلی |
| 1040 | دریافتنی از نمایندگان | کنترلی — با دفتر معین نمایندگان |
| 1050 | دریافتنی از شرکای فروش | کنترلی — با دفتر معین شرکا |
| 1060 | طلای خریداری‌شده در راه | کنترلی — خرید قطعی که هنوز به خزانه نرسیده |
| 1070 | پیش‌پرداخت‌ها و سایر دریافتنی‌ها | |
| 1080 | اعتبار مالیات بر ارزش افزوده خرید | |
| 1090 | واسط تأمین طلای آب‌شده (کسری پوشش) | فقط گرم؛ مانده‌ی مثبت = طلایی که هنوز باید خریده شود |
| 1095 | واسط مقداری شمش | فقط گرم؛ طرف وزنی خرید/فروش شمش و موجودی افتتاحیه |
| 1110 / 1120 | اموال و تجهیزات / استهلاک انباشته | |
| 2010 | بدهی ریالی به کاربران | کنترلی — با کیف پول‌ها |
| 2020 | بدهی طلایی به کاربران | کنترلی — با کیف پول‌ها |
| 2030 | مالیات پرداختنی | |
| 2040 | پرداختنی تأمین‌کنندگان طلا | کنترلی — با دفتر معین تأمین‌کنندگان |
| 2050 / 2060 | حقوق پرداختنی / سایر پرداختنی‌ها | |
| 3010 / 3020 | سرمایه / سود (زیان) انباشته | بستن سال مالی به 3020 منتقل می‌شود |
| 4010 … 4080 | درآمدها | کارمزد معاملات، فروش فروشگاه، بسته‌بندی، فروش و اجرت شمش، متفرقه نمایندگان، **سود ارزیابی و فروش طلا**، سایر |
| 5010 … 5180 | هزینه‌ها | پی‌رول، پاداش معرفی، تخفیف، کمیسیون نمایندگان، بهای تمام‌شده شمش، **زیان ارزیابی طلا**، **کارمزد شرکای اقساطی**، **کسری طلا**، اجاره، آب و برق، تبلیغات، کارمزد بانکی، حمل و بیمه، حقوق ریالی، استهلاک، اداری، سرور |

حساب‌های «کنترلی» فقط از مسیر عملیات سیستمی تغییر می‌کنند (سند دستی روی آن‌ها جز سند افتتاحیه مجاز نیست)
تا دفتر کل با کیف پول‌ها و دفاتر معین مغایرت پیدا نکند.

## ۳. خرید طلای آب‌شده توسط کاربر و خرید پوششی از بازار

### ۳-۱. اصل موضوع

وقتی کاربر طلای آب‌شده می‌خرد، شرکت **بدهکار طلا** به کاربر می‌شود؛ طلا به‌صورت خودکار وارد خزانه نمی‌شود.
معادل آن باید از بازار خریده و در خزانه نگهداری شود. پیش از این تغییر، هر خرید کاربر به‌طور فرضی موجودی خزانه (1020) را
بالا می‌برد و نقد (1010) را کم می‌کرد؛ اکنون:

| رویداد | بدهکار | بستانکار |
|---|---|---|
| خرید طلا توسط کاربر | 2010 بدهی ریالی (مبلغ + کارمزد + مالیات)<br>1090 کسری پوشش (گرم) | 2020 بدهی طلایی (ارزش، گرم)<br>4010 کارمزد — 2030 مالیات |
| فروش طلا توسط کاربر | 2020 (ارزش، گرم) | 2010 (خالص)، 4010، 2030<br>1090 (گرم) |
| پاداش معرفی / پی‌رول طلایی | 5020 یا 5010 (ارزش روز)<br>1090 (گرم) | 2020 (ارزش، گرم) |
| فروش اقساطی از طریق شریک | ر.ک. بخش ۵ | |

### ۳-۲. گزارش پوشش و خرید (خزانه ← پوشش و خرید طلا)

```
بدهی طلایی کاربران      = جمع طلای کیف پول‌ها
پوشش موجود              = موجودی خزانه (1020) + خریدهای قطعیِ در راه
طلای لازم               = بدهی × درصد هدف ÷ ۱۰۰ + ذخیره‌ی احتیاطی
کسری                    = طلای لازم − پوشش موجود
خرید پیشنهادی           = کسری − درخواست‌های پیش‌نویس  (گرد به واحد خرید)
```

تنظیمات (تنظیمات سیستم): `treasury.target_reserve_percent` (پیش‌فرض ۱۰۰)، `treasury.safety_buffer_grams`،
`treasury.purchase_lot_grams`، `treasury.alert_coverage_percent` (پیش‌فرض ۹۵ — زیر آن هر ساعت بررسی و روزی یک پیامک
هشدار برای مدیر ارشد/مالی ارسال می‌شود).

گزارش همچنین نشان می‌دهد: گردش روزانه (خرید/فروش کاربران، پاداش و حقوق، فروش شرکا، تحویل فیزیکی، خرید/فروش خزانه
و اختلاف)، آخرین خرید و تقاضای خالص از آن زمان، و مغایرت کیف پول‌ها با حساب 2020. خروجی اکسل و چاپ دارد.

### ۳-۳. چرخه‌ی خرید استاندارد

1. **درخواست خرید** از گزارش پوشش (یا سفارش جدید): پیش‌نویس با مقدار پیشنهادی و snapshot کامل گزارش برای ممیزی.
2. **قطعی‌سازی** پس از توافق قیمت با بنکدار (وزن ترازو، عیار ری‌گیری، قیمت هر گرم ۷۵۰، اجرت، کارمزد، مالیات):
   `بدهکار 1060 (بها، گرم ۷۵۰) + 1080 مالیات — بستانکار 2040 تأمین‌کننده (کل) + 1090 (گرم)`؛ کسری پوشش همین‌جا کم می‌شود.
   وزن مبنا = وزن ترازو × عیار ÷ ۷۵۰.
3. **رسید ورود به خزانه** پس از توزین و ری‌گیری: `بدهکار 1020 — بستانکار 1060` (همان بها و وزن) + محل نگهداری.
4. **پرداخت** (یک یا چند مرحله): `بدهکار 2040 — بستانکار 1010 (یا زیرحساب بانک)` و ردیف صورتحساب تأمین‌کننده.
5. **ابطال** پیش از رسید: سند برگشتی خودکار؛ مبلغ پرداخت‌شده به‌عنوان طلب از تأمین‌کننده باقی می‌ماند.

**فروش مازاد خزانه**: سفارش فروش؛ با ثبت، طلا به بهای میانگین از 1020 خارج، `بدهکار 2040` به خالص دریافتی و اختلاف به
4070 (سود) یا 5070 (زیان) می‌رود. **خرید شمش** از ضرابخانه هم با همین چرخه و حساب‌های 1025/1095 ثبت می‌شود.

### ۳-۴. شمارش خزانه

وزن شمارش‌شده ثبت و با دفتر مقایسه می‌شود. کسری: `بستانکار 1020 (بهای میانگین) — بدهکار 5090 کسری طلا + 1090 (گرم)`
(کسری دوباره در گزارش خرید ظاهر می‌شود تا جبران شود)؛ اضافی: `بدهکار 1020 — بستانکار 4080 + 1090`.

### ۳-۵. ارزیابی (تسعیر) طلا

ارزش ریالی 1020 و 2020 با قیمت روز برابر و اختلاف به 4070/5070 منتقل می‌شود (پیش‌نمایش قبل از ثبت). پیشنهاد:
پایان هر ماه و قبل از بستن سال مالی. موجودی شمش به بهای تمام‌شده باقی می‌ماند.

## ۴. موجودی شمش

هر شمش کددار یکی از این وضعیت‌ها را دارد:

| سبد | شرط | معنی |
|---|---|---|
| کد خام | `UNASSIGNED` بدون وزن | کد چاپ‌شده که هنوز به شمشی متصل نیست |
| کددار در خزانه | `UNASSIGNED` با وزن | شمش فیزیکی خزانه که کد خورده و آماده‌ی فروش/تحویل امانی است |
| نزد نماینده | `AT_AGENT` | امانی نزد نماینده (با تفکیک نماینده) |
| در انتظار گیرنده | `TRANSFER_PENDING` | خرید برای شخص دیگر، منتظر تأیید گیرنده |
| فروخته‌شده | `ASSIGNED` | دارای مالک فعال — کانال: فروشگاه / نماینده / شریک |
| فروخته — در انتظار کد | ردیف سفارش پرداخت‌شده بدون کد | باید کدگذاری و ارسال شود |
| موجودی فروشگاه | `stockQuantity` تنوع‌ها | شمش بدون کد قابل فروش در کاتالوگ |

**کدگذاری شمش خزانه** (موجودی شمش ← کدگذاری): هر خط «کد، وزن، عیار، سریال». اثر حسابداری ندارد.

اسناد: فروش فروشگاه `بدهکار 5060 — بستانکار 1025` (گرم + بهای میانگین) و در لغو، برگشت همان سند؛
تحویل امانی `1025 → 1030` و فروش نماینده `5050 ← 1030` با بهای میانگین.

## ۵. شرکای فروش (اسنپ‌پی، دیجی‌پی و اپ‌های همکار)

### ۵-۱. مدل همکاری

مشتری طلا را از طریق شریک (به‌صورت اقساطی یا در اپ شریک) می‌خرد؛ شریک پرداخت را تضمین و **مبلغ منهای کارمزد** را
طبق قرارداد (T+N روز) به آرکان تسویه می‌کند. ریسک اعتباری اقساط با شریک است؛ پیش‌پرداخت و طرح اقساط فقط برای اطلاع ثبت می‌شود.

تنظیمات هر شریک: نوع همکاری، آداپتور (SNAPPPAY / DIGIPAY / TARA / LENDO)، درصد و مبلغ ثابت کارمزد، مهلت تسویه،
سقف طلب، حداقل/حداکثر سفارش، کالاهای مجاز (آب‌شده / شمش)، قرارداد، اطلاعات بانکی، کلید API و IPهای مجاز.

### ۵-۲. چرخه‌ی سفارش

| وضعیت | رویداد | اثر |
|---|---|---|
| در انتظار | ثبت از پنل یا API (کلید idempotency = شناسه‌ی مرجع شریک) | قیمت قفل؛ بدون اثر مالی |
| تأییدشده | شریک پرداخت را تضمین کرد | آب‌شده: واریز طلا به کیف پول (تراکنش «خرید اقساطی طلا»)؛ شمش: ثبت مالکیت شمش کددار؛ سند فروش و فاکتور |
| تسویه‌شده | ثبت واریز شریک | سفارش‌ها به تسویه متصل می‌شوند (انتخابی یا خودکار به ترتیب سررسید) |
| لغوشده | لغو پیش از تأیید | — |
| مستردشده | استرداد پس از تأیید | کسر طلا از کیف پول (باید آزاد باشد) یا باطل‌شدن مالکیت شمش؛ سند برگشتی؛ فاکتور باطل |

مشتری باید در آرکان گلد ثبت‌نام و احراز هویت کرده باشد (کد ملی با شماره تطبیق داده می‌شود).

### ۵-۳. اسناد

| رویداد | بدهکار | بستانکار |
|---|---|---|
| تأیید (آب‌شده) | 1050 دریافتنی از شریک (خالص)<br>5080 کارمزد شریک<br>1090 (گرم) | 2020 بدهی طلایی (ارزش، گرم)<br>4010 کارمزد خدمات — 2030 مالیات |
| تأیید (شمش) | 1050 — 5080<br>5060 بهای تمام‌شده (گرم، بها) | 4040 ارزش طلا — 4050 اجرت — 4010 — 2030<br>1025 (گرم، بها) |
| تسویه | 1010 بانک | 1050 |
| استرداد | معکوس سند تأیید | |

اگر سفارش تسویه‌شده مسترد شود، مانده‌ی شریک منفی (بدهی ما به شریک) می‌شود و در تسویه‌ی بعدی جبران می‌شود.

### ۵-۴. گزارش‌ها

فهرست شرکا با فروش، طلب تسویه‌نشده و معوق؛ گزارش عملکرد دوره‌ای و **سنی مطالبات** (جاری، ۱–۷، ۸–۳۰، +۳۰ روز)؛
صورتحساب هر شریک؛ فهرست سفارش‌ها با فیلتر معوق. مشخصات API در [partner-api.md](../partners/partner-api.md).

## ۶. اسناد دستی، هزینه‌ها و دوره‌ی مالی

- **ثبت هزینه**: فرم سریع (نوع هزینه + پرداخت از بانک/صندوق یا پرداختنی + مبلغ + مدرک).
- **سند عمومی/اصلاحی/افتتاحیه**: چندسطری با ستون‌های ریال و گرم؛ تراز بودن پیش از ثبت کنترل می‌شود.
- **کنترل دوگانه**: تأیید باید توسط شخصی غیر از ثبت‌کننده باشد (`accounting.allow_self_approve` برای تیم‌های کوچک).
- **برگشت**: سند ثبت‌شده حذف نمی‌شود؛ فقط سند برگشتی صادر می‌شود.
- **قفل دوره** (`accounting.locked_until`): ثبت سند دستی با تاریخ قبل از آن ممنوع.
- **قطعی‌سازی**: شماره‌ی دائم ترتیبی بدون فاصله در هر سال مالی و قفل تا همان تاریخ.
- **بستن سال**: مانده‌ی ریالی درآمدها و هزینه‌ها با سند اختتامیه به 3020 منتقل و دوره قفل می‌شود.

## ۷. مغایرت‌گیری

صفحه‌ی مغایرت‌گیری این کنترل‌ها را اجرا می‌کند: تراز آزمایشی، برابری مانده‌ی ذخیره‌شده‌ی هر حساب با جمع سطرهای آن،
2010 و 2020 با جمع کیف پول‌ها، 1040 با صورتحساب نمایندگان، 1030 با وزن شمش‌های «نزد نماینده»، 1050 با مانده‌ی شرکا،
2040 با مانده‌ی تأمین‌کنندگان، و 1060 با خریدهای قطعیِ در راه.

| `partner.view` / `partner.manage` / `partner.order.manage` / `partner.settlement.manage` | شرکای فروش |

نقش جدید **حسابدار** (`ACCOUNTANT`): ثبت سند و هزینه، مشاهده‌ی دفاتر، خزانه، شرکا و موجودی شمش (تأیید با مدیر مالی).
**مدیر مالی** همه‌ی دسترسی‌های حسابداری، خزانه و شرکا را دارد؛ **مدیر فروشگاه** مشاهده و کدگذاری موجودی شمش.

## ۹. راه‌اندازی روی داده‌های موجود (یک‌بار)

1. `prisma migrate deploy` (مهاجرت `20260926090000_advanced_accounting`) و ری‌استارت API تا حساب‌های جدید seed شوند.
2. **سال مالی** جاری را تعریف کنید.
3. **شمارش خزانه‌ی طلای آب‌شده**: چون قبلاً هر خرید کاربر خزانه را به‌طور فرضی بالا می‌برد، موجودی دفتری 1020 احتمالاً
   بیش از موجودی واقعی است. وزن واقعی را در «شمارش خزانه» ثبت کنید؛ کسری به 1090 (نیاز به خرید) و 5090 می‌رود.
   سپس نقد 1010 را با صورت‌حساب بانک تطبیق دهید و اختلاف (خریدهای فرضی قبلی که از نقد کسر شده بودند) را با سند اصلاحی
   `بدهکار 1010 — بستانکار 5090` اصلاح کنید.
4. **سند افتتاحیه‌ی شمش**: `بدهکار 1025 (بها، گرم) — بستانکار 3010 (بها) و 1095 (گرم)`؛ امانی نمایندگان نیز در صورت نیاز
   با بدهکار 1030 (بها) اصلاح شود. سپس شمش‌های موجود خزانه را کدگذاری کنید.
5. سرمایه و سایر مانده‌های افتتاحیه (اموال، بدهی‌ها) را با سند افتتاحیه ثبت کنید.
6. صفحه‌ی **مغایرت‌گیری** را بررسی و موارد را با سند اصلاحی رفع کنید.
7. تأمین‌کنندگان، شرکای فروش و زیرحساب‌های بانکی را تعریف کنید.

## ۱۰. آزمون

`api/src/treasury/advanced-accounting.integration.spec.ts` کل چرخه را روی PostgreSQL واقعی آزمایش می‌کند
(خرید کاربر ← پوشش ← خرید ← رسید ← پرداخت ← فروش اقساطی/تسویه/استرداد ← سند افتتاحیه با کنترل دوگانه ← کدگذاری و فروش شمش
← ارزیابی ← تراز، ترازنامه و مغایرت‌گیری ← شمارش خزانه ← بستن سال مالی):

```bash
cd api
DATABASE_URL=postgresql://... npx prisma migrate deploy
INTEGRATION_DATABASE_URL=postgresql://... npx jest advanced-accounting
```
